# 天正并发任务入口

当前设置（2026-11-20）：最多 **5 个 CAD 工作进程同时运行**；运行、停止中、待人工排障和排队合计最多 **5 个未结束任务**。历史成功/失败任务不占容量。第 6 个任务明确拒收，可在有任务结束后重提。

入口：`.\cad_pool\pool.ps1`。此入口只负责调度和隔离，不替代 electrical-dwg 的几何、回路和交付检查。所有聊天使用同一个入口，不能各自建立一个“三并发”池。原先绕过入口启动的 CAD 不受本池管理，也不会被本池终止。

## 提交与查看

```powershell
& '.\cad_pool\pool.ps1' -Action submit -Package 'D:\项目准备目录\任务包' -Name '项目名称'
& '.\cad_pool\pool.ps1' -Action start
& '.\cad_pool\pool.ps1' -Action status
```

`start` 启动隐藏的轻量调度器，不预开空闲 CAD；重复运行不会建立第二个调度器。提交后记录返回的任务 ID 和 root。默认启动超时 180 秒，每任务运行超时 3600 秒，可在 `config.json` 中调整并重启调度器。没有自动重跑失败任务，修正原因后提交新运行目录，保留原证据。

```powershell
# 取消指定任务，仅操作本任务持有的进程
& '.\cad_pool\pool.ps1' -Action cancel -JobId '返回的任务ID'
# 暂停调度；已启动任务继续受其启动器监督
& '.\cad_pool\pool.ps1' -Action stop
```

调度器不注册开机自启；后续任务使用时运行 `start`。`init` 用于首次初始化或更新编译，存在运行任务时拒绝执行，不需要每次提交都初始化。

## 任务包契约

目录必须包含 `job.json`、`scripts/command.scr`；原图副本及数据放 `input/`。只有 `input/`、`scripts/` 被复制到新建的唯一任务目录，旧状态、结果、输出不被复制。

`job.json` 示例：

```json
{
  "isolationContract": 1,
  "validationReport": "output/validation.json",
  "expectedOutputs": ["output/项目_电气.dwg", "output/校核.pdf"]
}
```

提交时由调度器添加 `jobId`。任务根目录从进程环境变量 `CAD_POOL_JOB` 获取；任务 ID 从 `CAD_POOL_JOB_ID` 获取。LISP 可用 `(getenv "CAD_POOL_JOB")`，C# 可用 `Environment.GetEnvironmentVariable("CAD_POOL_JOB")`。输入路径、插件配置和输出均由任务根目录派生，不硬编码历史项目路径。

`command.scr` 执行本项目的原生绘图及完整检查。所有临时 LISP、请求文件、JSON、检查点和结果必须位于本任务目录；加载的任务插件放 `scripts/`。保持 `FILEDIA=0`、`CMDDIA=0`、`BACKGROUNDPLOT=0`；禁止 GetActiveObject/GetObject 连接任意已有 CAD，禁止跨任务写入共享天正 sys 目录。每个进程独占本任务文档，处理异步 SendStringToExecute 时要串起完成回调，不能提前报告完成。

最终 DWG 独立原生回读、工程与版式验收全部通过后，生成指定报告，至少包含：

```json
{"jobId":"本任务ID","passed":true,"checks":{"nativeReadBack":true}}
```

随后调用 `CADPOOLCOMPLETE`。调用前必须完成全部保存，关闭写文件流、PDF出图和原生回读事务；不能依赖退出时自动保存。桥接器核对任务身份、报告通过和必备文件存在，原子写入 `control/result.json`，然后直接结束本次专用进程，避免隐藏的退出/保存对话框；不保存临时会话和Profile运行期变化。它不替代报告内的专业检查。任何失败使用 `CADPOOLFAIL`，或保留错误让超时监督退出。报告缺失、失败、身份错误或输出缺失都不会判为成功。

## 隔离与边界

### 2026-11-20 云插件启动阻塞处理

用户已授权由并发协调聊天将当前 Windows 用户 AutoCAD 2020 的公共 `Applications/CP_ARX`、`Applications/CP_NET` 两项 `LOADCTRLS` 从2改为0，停止其自动加载；原始注册表导出和回读记录位于 `diagnostics/startup-cloud_20261120/apply_20261120_164525/`。此项影响以后新开的普通CAD与后台CAD，不卸载插件，不关闭已有进程。此分支在Profile之外，不属于各槽位独立配置。

项目任务不得为启动/重试再临时改这两项并恢复为2；需要恢复云插件时由协调聊天统一安排，使用备份并复核。调整后的启动/原生回读测试结果见同诊断目录，尚无测试结果时不得声称故障已经解决。

- 五个槽位 W01～W05 各自使用复制自 TArch20V8 的独立 Profile、独立打印配置；一次运行创建独立隐藏 Windows desktop 和 acad.exe。
- 每次运行有独立 TEMP/TMP、自动保存、日志、控制目录、脚本、输出和工作副本。启动器一直持有目标进程句柄，取消及超时只终止该句柄对应的 CAD。
- 状态更新使用系统互斥锁和原子替换；启动器有每槽位独占锁。启动握手核对 PID、槽位和任务 ID。启动器丢失且无法核实进程归属时保留槽位阻塞，不冒险复用。
- 后台桥接器提供心跳，但长时间原生命令可能阻塞 UI 心跳，因此不会仅凭心跳过期误杀；采用启动超时、总运行超时及进程状态判断。
- 规则、字体、样板等公共资源只读。运行期间不要改公共插件和样板；项目脚本需要在提交前消除历史共享路径。
- 任务聊天只处理自己的任务ID，不停止整个调度器、不批量结束CAD、不修改其他槽位Profile。并发池程序、配置及公共插件的变更由一个协调入口统一处理；正在执行的脚本和已提交的任务包不就地覆盖。
- 这是同一 Windows 用户下的进程与文件隔离，不是虚拟机安全边界，也不隔离天正内部所有注册表/全局缓存。不可信脚本不应提交。
