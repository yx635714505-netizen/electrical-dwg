# CAD 池启动与续作排查

## 先定位失败阶段

从仓库根目录运行 `./cad_pool/pool.ps1 -Action status`，按本次任务 ID 找到任务目录。记录提交时间、槽位和状态，检查该任务的 `control`、`logs` 和输出目录。区分排队、启动 CAD、进入绘图脚本、保存、回读和试打所耗的时间。

| 观察到的证据 | 下一步 |
| --- | --- |
| 任务仍在队列 | 核对运行中的槽位和本任务状态。重复提交会占用同一池的剩余名额。 |
| 有进程记录，缺少 ready 回执和绘图开始标记 | 核实进程是否属于本任务、实际 Profile、模板和启动日志，再用小型诊断任务区分 CAD 启动与项目绘图故障。 |
| ready 回执存在，绘图开始后中断 | 查看本任务脚本的最后一条成功命令、插件加载和输入文件版本。按原生回读、组图、打印等实际步骤定位失败点。 |
| 目录中已有 DWG | 对照退出记录、最终 DWG 哈希、原生回读及试打报告，区分检查点与可交付成果。 |

自动加载模块的名称、空日志或超时只能说明观察到的状态。若怀疑某插件影响启动，在池空闲时由负责公共配置的人安排单变量对照，保存两次结果。操作限定在已确认归属的任务、进程和槽位。

## 恢复后续作

核对源 DWG、任务包、规则和上次检查点的版本，记录已完成步骤及缺失证据。使用同一个共享池重新提交，关联新旧任务记录。修订时先试打受影响页，定稿用最终保存的 DWG 统一回读并试打全套，按实际覆盖记录待核项。分别记录排队、启动、生成、重试和验收时间，保留并行重叠。
